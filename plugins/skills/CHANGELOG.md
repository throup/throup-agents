# Changelog

All notable changes to the `skills` plugin. Versions follow [semver](https://semver.org/).

## 0.4.1

- `skill-audit`: cut by a second audit of the skill with itself. Recorded suggestions are decided
  after the audit unless the operator's guidelines have them decided within it; the stage-one
  reading takes the purpose's shape; the loaded-on-other-machines check reports a missing
  directory.

## 0.4.0

- `skill-audit`: a finding that offers keeping a reason being cut or cutting the rule it supported
  goes to the operator as that choice.
- `skill-audit`: where an operator's ruling changes or narrows what the skill is for, the confirmed
  purpose and the skill's opening are rewritten in the same step, the operator confirms the new
  purpose, and later reviewers judge against it.
- `skill-audit`: for a tracked skill, the auditor checks its own primary working directory, branch
  name and recent commit subjects for the audit branch, ticket key and audit commit subjects before
  each blind reviewer launches. Each reviewer also records the working directory, branch name and
  commit subjects its session loaded, and the report names each reviewer's exposure from both.

## 0.3.0

- `skill-audit`: for a skill the operator confirms is loaded on other machines, the authorities are
  the repo files that load wherever the skill loads and the skills it points to, so a rule stated
  only in the user's guidelines or memory stays in the skill, and a conflict with those guidelines
  goes to the operator as a possible local override, and otherwise to keep, reword or cut. The audit
  proposes the answer from whether the skill is tracked in a repo with a remote.
- `skill-audit`: an action whose only statement is a reason being cut stays in the skill.
- `skill-audit`: a fix made after the blind review changes only the sentence its finding cites; a
  rewording that changes a rule's scope goes to the operator first, and later reviewers are told the
  ruling.
- `skill-audit`: stage two of the brief names the version of the skill that produced each artefact.
- `skill-audit`: an untracked skill's backup goes to a new directory each time, so a second audit
  never overwrites the first's baseline.

## 0.2.2

- `skill-audit`: cut by an audit of the skill with itself; its opening states the skill's purpose.

## 0.2.1

- `skill-audit`: on the handover route the blind reviewer may remove the handover's symlink when it
  closes it, and the auditor removes any symlink still in place once it is done with that reviewer,
  so no pointer to the handover is left in the checkout.

## 0.2.0

- `skill-audit`: the blind reviewer states what the skill is for from the cut alone, before the
  confirmed purpose, the baseline and the skill's artefacts are sent to it; the report shows that
  reading beside the purpose.
- `skill-audit`: every edit made after the blind review goes to a new blind reviewer before the
  audit is done, on the tracked and the untracked route; its findings go to the operator.

## 0.1.0

- `skill-audit`: cut one skill to the sentences its confirmed purpose needs and no authority
  already states, then have a fresh blind reviewer judge the cut against that purpose and a
  baseline.
